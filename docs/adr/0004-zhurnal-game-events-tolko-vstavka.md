# 0004. Журнал `game_events` только на вставку как дедуп между сайтом и ботом

## Контекст
Закрывать прошедший день и начислять награды и штрафы могут и сайт (при открытии, раз в минуту), и бот. Старая геймификация считалась в апдейтерах состояния и без истории: стрик +1 при открытии без проверки действий, награды можно было начислить дважды, ачивки без истории не посчитать.

## Решение
Все правила наград лежат в одном модуле `shared/gamification` (`applyEvent`). Каждое событие пишется в журнал `game_events` с ключом `(user_id, id)`, где id = `${kind}:${ref}`. Журнал только на вставку (insert с `ignoreDuplicates`, политика insert+select). Сайт и бот сначала вставляют событие и применяют статы, только если вставка прошла, то есть событие не дубль.

## Почему
- «Сайт считает, бот читает» отвергнуто: бот сам закрывает пропущенные дни, когда сайт закрыт.
- Флаг «день закрыт» в `game_stats` отвергнут: два писателя прочитают его одновременно и оба применят день. Уникальный ключ вставки даёт атомарность без блокировок.
- Допустить UPDATE и DELETE журнала отвергнуто: ачивки и итоги считаются по истории, перезапись сделала бы их нечестными.
- Награды внутри апдейтеров React-состояния отвергнуты: старый код читал статы из замыкания, и две награды подряд теряли одну.

## Последствия
- Любое новое начисление обязано иметь детерминированный id события, иначе дедуп не сработает или схлопнет разные события.
- Ошибку в записанном событии нельзя исправить правкой: нужно компенсирующее событие.
- Журнал растёт без ограничений.
- Если вставка прошла, а применение статов упало, награда потеряна: повторная вставка вернёт «дубль».
