# 0008. Общие правила в `shared/`, которые компилирует и сайт, и сервер (strict CommonJS)

## Контекст
Правила таймера, целей, каналов, Big Data и наград должны давать одинаковый результат на сайте и в боте, иначе они посчитают день по-разному (см. 0004). Сайт собирается Vite, сервер — Node 22 и TypeScript.

## Решение
Чистые детерминированные функции без React, сети и DOM лежат в `shared/`, время приходит параметром `now`. Сайт импортирует их через алиас `@shared/*`, сервер компилирует их своей сборкой. Поэтому код в `shared/` — строгий TypeScript без DOM, компилируемый в strict CommonJS. Проверка: `cd server && npm run build` должен проходить.

## Почему
- Дублирование правил в сайте и сервере отвергнуто: награды, штрафы и расписание разойдутся при первой правке одной стороны.
- Вызов правил сервером через сайт по HTTP отвергнут: сервер не должен зависеть от хостинга сайта.
- Отдельный npm-пакет отвергнут как лишний механизм публикации для одного репозитория и одного владельца.

## Последствия
- DOM-обращение или ESM-only синтаксис в `shared/` ломает сборку сервера, а не сайта: ошибка проявляется далеко от места правки.
- Каждый новый модуль в `shared/` нужно проверять `cd server && npm run build`.
- Сервер подгружает `remindersFor` из `shared/channels` через `require` в рантайме; переименование экспорта сломает бота без ошибки сборки сайта.
- Изменение правил сразу действует и на сайт, и на бота, поэтому нужны тесты Vitest.
