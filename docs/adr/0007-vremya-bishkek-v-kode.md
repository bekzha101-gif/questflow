# 0007. Время по Asia/Bishkek в коде, системный пояс не трогаем

## Контекст
Пользователь просил настроить часовой пояс под Бишкек. «Сегодня» определяют сайт (браузер Mac и телефон), сервер (Windows) и cron-расписания утра и вечера. В старом коде «сегодня» считалось через `toISOString().split('T')[0]`, то есть по UTC.

## Решение
Один модуль `shared/time` с `APP_TZ = 'Asia/Bishkek'` (UTC+6): `todayStr`, `dayOfWeek`, `isRecoveryDay`, `addDays`, `weekStart`, `monthKey`. Сайт и сервер определяют день, пятницу, неделю и месяц только через него. Расписания cron указывают пояс явно. Системный пояс Windows не меняется.

## Почему
- Менять пояс Windows отвергнуто: это системная настройка компьютера, она затронет всё остальное на нём; пользователь может сделать это сам.
- Пояс устройства или браузера отвергнут: три клиента в разных поясах по-разному решат, какой сегодня день, и закрытие дня разойдётся.
- `toISOString().split('T')[0]` отвергнут: между 00:00 и 06:00 по Бишкеку он возвращает вчерашнюю дату.

## Последствия
- Использовать `toISOString().split('T')[0]` для «сегодня» запрещено: это правило проекта.
- Если владелец переедет, приложение продолжит жить по Бишкеку; менять придётся константу.
- Логи и системное время Windows показывают другой пояс, чем бот; при разборе сбоев это путает.
