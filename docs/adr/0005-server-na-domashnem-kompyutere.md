# 0005. Сервер бота на домашнем компьютере: long polling и свои расписания

## Контекст
Нужен Telegram-бот с состоянием разговора, голосом, расписаниями по Бишкеку и анализом через Claude по подписке Max. Пользователь подтвердил: сервер — этот Windows-компьютер (Xeon, 128 ГБ, RTX 2060). Бюджет не ограничен.

## Решение
Сервер — Node 22 + TypeScript в `server/` этого репозитория: grammY с long polling, `node-cron` в `Asia/Bishkek` (тик раз в 30 с), service-role ключ из `server/.env`. Автозапуск — задача Планировщика Windows «при запуске» плюс обёртка, перезапускающая процесс при падении. Бот отвечает только владельцу: первый `/start` привязывает chat id.

## Почему
- Supabase Edge Functions с cron отвергнуты: оттуда нельзя вызвать Claude по подписке и нельзя запустить бесплатный Whisper на видеокарте. Расписание они бы держали, но разговор с состоянием и голос неудобны и платны.
- Webhook отвергнут: нужен открытый порт на домашнем компьютере; long polling его не требует.
- Арендованный сервер отвергнут: на нём нет входа в аккаунт Claude Max и видеокарты для Whisper, а стоимость не нулевая.

## Последствия
- Бот живёт, пока включён этот компьютер и есть интернет; выключили или завис Windows, и молчат утро, вечер и таймер.
- Служба обязана работать под пользователем Administrator: вход Claude привязан к его профилю.
- Секреты (токен бота, service-role) лежат файлом на этом компьютере; они не в репозитории и не на сайте.
- Установщик `npm run setup` и скрипты автозапуска приходится поддерживать.
- Расписание держит только этот сервер; второй экземпляр запускать нельзя, он продублирует сообщения.
