# 0009. Состояние таймера в облаке, управление только на сайте, в Telegram только уведомления

## Контекст
Таймер был будильником на планшете. Старый таймер сбрасывался при паузе и при закрытии вкладки, состояние жило в браузере. Пользователь хочет уведомления «пора на отдых», «отдых закончился», «ты проработал 2ч 00м» и ответил: «хочу, чтобы таймер работал только в сайте, а не в тг».

## Решение
Состояние таймера хранится в `timer_state` в Supabase; время считает чистая функция по `started_at` и накопленным секундам (`computeTimer`). Цикл — 3 блока по 120 мин с отдыхом 20 мин, следующий блок сам не стартует. Управлять таймером можно только на сайте. Сервер раз в 30 с проверяет состояние и шлёт уведомления в Telegram; кнопок управления в боте нет. Блок, закончившийся при закрытом сайте, засчитывается по фактическому времени.

## Почему
- Управление таймером из Telegram отвергнуто прямо пользователем.
- Хранение только в браузере отвергнуто: сервер тогда не знает о конце блока и не пришлёт уведомление при закрытом сайте.
- Счёт тиками отвергнут: при закрытой вкладке тики не идут, отсюда исходный баг.
- Web Push отвергнут: при закрытом сайте он не закрывает Mac и Android; эту роль берут Telegram-уведомления, которые приложение Telegram показывает системным уведомлением.
- Автостарт следующего блока отвергнут: перед блоком пользователь выбирает задачу.

## Последствия
- Уведомление приходит с задержкой до ≈ 30–60 с после окончания.
- У таймера два писателя (сайт и сервер); защита от двойных уведомлений — `notified_end` и ключи дедупа в `bot_settings.last_sent`.
- Два открытых окна сайта не должны дублировать уведомления: для этого есть `claimTimerEvent`.
- Если сервер выключен, уведомлений в Telegram нет, а сам счёт на сайте остаётся верным.
