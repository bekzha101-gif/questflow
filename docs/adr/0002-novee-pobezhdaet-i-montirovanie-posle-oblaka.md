# 0002. Метка `updated_at`, «новее побеждает» и монтирование приложения только после чтения облака

## Контекст
Данные правят три источника: сайт на Mac, сайт на телефоне и бот на сервере. Кеш и очередь могут отправить старую версию строки после новой, а при первом запуске в кеше лежит запасное значение, а не данные пользователя.

## Решение
Каждая строка несёт `updated_at`. Триггер в базе игнорирует UPDATE, если присланная метка не новее текущей; `null` превращается в `now()`. Сервер и бот обязаны слать `updated_at` сами. Запасная метка `1999-01-01` ставится только записям, которые сайт сделал автоматически из запасного значения, пока облако не прочитано; облако такую запись всегда перебивает. Приложение монтируется только после проверки входа и чтения облака этого пользователя. Сиды создаются после чтения облака. Быстрый вход с паролем удалён.

## Почему
- «Последний пришедший побеждает» отвергнуто: порядок прихода зависит от сети и очереди, а не от времени правки; старая версия из очереди затёрла бы новую.
- Блокировки или векторы версий отвергнуты как избыточные для одного владельца с тремя клиентами: хватает построчной метки времени.
- Монтирование без ожидания облака отвергнуто: приложение тогда пишет запасные значения поверх данных, которых ещё не видело. Метка 1999 закрывает остаточный случай автозаписей, но главная защита — не показывать приложение раньше времени.
- Метка 1999 для всех записей отвергнута: настоящая правка пользователя с ней проигрывала бы облаку. Поэтому только для автозаписей.

## Последствия
- На старте приложение ждёт сеть: при медленном облаке пользователь видит экран ожидания.
- Любой клиент, пишущий в базу, обязан слать корректный `updated_at`; кто забудет, получит тихо проигнорированный UPDATE.
- Часы клиентов участвуют в разрешении конфликтов: телефон с неверным временем может проиграть или выиграть чужую правку.
- Перенесённые строки и сиды имеют метку 2000-01-01, любая правка их перебивает.
