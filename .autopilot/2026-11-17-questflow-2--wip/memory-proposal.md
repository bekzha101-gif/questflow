# Предложение для `CLAUDE.md`

`CLAUDE.md` принадлежит пользователю и не менялся. Каждая строка ниже готова к вставке; куда вставлять — в заголовке группы.

## A. Добавить в «Стек и команды» (команды проверены независимым запуском)

1. `npm run check` — одна проверка: тесты + типы + сборка + lint; сейчас 211 passed. Её запускай перед коммитом вместо одного `npm run build`.
2. `npm test` — 211 тестов сайта и `shared/` (Vitest). Один файл: `npx vitest run shared/time.test.ts` (проверено, 7 passed).
3. `cd server && npm install && npm test && npm run build` — сервер, 78 тестов. Один файл: `cd server && npx vitest run src/db.test.ts` (проверено, 3 passed).
4. `npx vite preview --port 4791` — посмотреть собранный сайт (после `npm run build`).
5. `cd server && npm run setup` — спрашивает токены и пишет `server/.env`; `cd server && npm run dev` — собрать и запустить бота.

## B. Добавить: переменные окружения (только имена)

6. Сайт (`.env.local`, шаблон `.env.example`): `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`; необязательные `VITE_GEMINI_API_KEY`, `VITE_YOUTUBE_API_KEY`, `VITE_GOOGLE_CLIENT_ID`. В сайт идёт только anon-ключ.
7. Сервер (`server/.env`, шаблон `server/.env.example`): `TELEGRAM_BOT_TOKEN`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `OWNER_USER_ID`; необязательные `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `WHISPER_PYTHON`, `WHISPER_MODEL`, `WHISPER_DEVICE`. Значения в репозиторий, чаты и логи не попадают.

## C. Добавить: подводные камни

8. Сайт работает с данными только через `src/store` (`useCollection`, `useRecord`); компоненты не трогают `localStorage` и не ходят в Supabase напрямую.
9. Удаление мягкое (`deleted = true`); любой запрос фильтрует удалённое. Сервер обязан слать `updated_at`, иначе триггер БД отбросит запись.
10. `shared/` собирается сервером как строгий CommonJS без DOM: после правки в `shared/` проверяй `cd server && npm run build`.
11. Дату «сегодня» бери только из `shared/time.ts` (Asia/Bishkek); `toISOString().split('T')[0]` не использовать.
12. Миграцию `supabase/migrations/002_questflow2.sql` к боевой базе без разрешения пользователя не применять; в `.github/workflows/deploy.yml` и `.env.production` лежат литералы `VITE_*` (anon-ключ публичный), секретов и service-role там быть не должно.
13. Не пушить и не деплоить без просьбы; сам `git push` в `master` по-прежнему только по просьбе (см. «Как работать со мной»).

30. Подраздел «История git» (рядом с предыдущим):

```markdown
### История git

Целиком не читай — бери срез под вопрос:

| Вопрос | Команда |
|---|---|
| что правили после последней сборки | `git log --oneline "$(git log -1 --format=%h --grep='^Autopilot: сборка сдана')"..HEAD -- . ':(exclude).autopilot'` |
| всё, что делали ради требования | `git log --oneline --grep="R02"` |
| история файла | `git log --oneline -10 -- <файл>` |
| когда появился или исчез код | `git log --oneline -S "<фрагмент>"` |
| почему строка такая | `git blame -L <с>,<по> <файл>`, затем `git show <sha>` |
| что внутри коммита | `git show --stat <sha>` |

Срез длиннее ~30 коммитов — отдай его субагенту и возьми выжимку в десять строк.

Коммит: заголовок — что (`fix: даты в одном формате`), тело — почему, трейлеры
`Autopilot-Run: <папка сборки>` для правок автопилота и `Requirements: R02`, если правка
касается требования из `manifest.md`. Заголовок `Autopilot: сборка сдана` пишет только автопилот — по нему находят последнюю сборку.
```

   Примечание: в `git log` пока нет ни одного коммита `Autopilot: сборка сдана`, поэтому первая команда таблицы до сдачи сборки вернёт пустой срез; тогда смотри `git log --oneline -20`.
