**Баги синка (высокий риск, учесть при «сервер читает Supabase»)**:

Итог: после паузы счётчик возвращается к полному времени, при «Старт» в `persistCurrentState({isRunning:true,startTime})` уходит accumulated=0 → накопленное время в localStorage теряется. «Стоп» после паузы даёт `currentElapsed 0 < 15` → лог не пишется. Главный кандидат на «таймер сам сбрасывается». Правильный фикс: зависимость только от изменения длительности/режима, не от isRunning.
2. `handleFinishSession` использует `elapsedSecondsRef`, а ref обновляется эффектом (стр.207), в паузе рассинхрон с `accumulatedSecondsRef`.
3. Эффект тика замыкает устаревший `handleFinishSession` (lint exhaustive-deps, стр.294). Внутри в основном refs, но `onLogSession`/`onCompleteTask` берутся из первой отрисовки эффекта → логи с устаревшим `calendarConfig` в `App.handleLogSession`.
4. Интервал `setInterval` в фоновой вкладке throttled, но считается от `Date.now()`, это нормально. Реальный риск: в iOS PWA JS стоит в фоне, уведомление/звук окончания не сработают, пока приложение не открыто (нет серверного пуша).
5. `timerType === 'stopwatch'` никогда не «истекает», автоперехода нет.
6. Хардкод дефолтов (`'task-notebook-ideas'`, заголовок «Подчесать всю тетрадь…») (стр.115,121).
7. Дубль формул EXP/золота в трёх местах (handleConfirmExpiredSession, handleFinishSession work, naturalLanguageParser). Для переработки 120/20 вынести в один модуль.

### Вероятные причины «иногда работает, иногда нет»
1. Будильники живут только пока компонент смонтирован: нужно открыть вкладку Здоровье или модалку; на другом экране/закрытой вкладке ничего не звонит. На телефоне (PWA в фоне) JS заморожен.
2. Сканер `useEffect` перезапускается при каждом изменении `protocol/alarms`; тик раз в 30 с, окно медитации 15 мин → звук повторяется каждые 30 с до отметки «сделано».
3. `playHealthAlarmSound` создаёт новый `AudioContext` на каждый вызов (без `resume()`, без закрытия): политика автоплея браузера блокирует звук, пока не было жеста пользователя после загрузки; контексты накапливаются (лимит).
4. Звук/баннер есть только для медитации; `water/walk/gadgets_off/sleep` лишь выставляют флаги в `scanStatus` (баннер), поля `soundEnabled` и `repeatDaily` в `scanHealthAlarms` **не читаются**; `enabled` учитывается только как `a.enabled` для 3 типов (water-будильника нет вовсе).
5. `protocol` грузится на `today` в момент монтирования (`loadDailyProtocol(today)`), через полночь без перезагрузки остаётся вчерашним (дата зафиксирована при монтировании; `today` константа в теле компонента, строка ~72).
6. `Notification.permission` часто `default/denied`, на iOS `new Notification` вообще недоступен без service worker `showNotification` и установленного PWA. Аналогично `sendDesktopNotification` (`recoveryCycle.ts:204`) использует `new Notification` и `icon:'/favicon.ico'` (при `base:'./'` и деплое в подпапку GitHub Pages путь неверный).
7. Данные дня `health_daily_<date>` — ключ на каждый день, копится без чистки.
8. Для Telegram-бота: нужна выгрузка будильников/приёма пищи в Supabase и серверный планировщик; сейчас на сервере этих данных нет.
